01

One loop, applied everywhere

Before the refactor, SAR was optional middleware that only a handful of duties used; the rest ran arbitrary execute() methods, and coordination, planning, and scheduling each had their own engine. Now SAR is enforced at the runner: the registry executes every Duty inside a SAR chain, so budgets, model resolution, and tracking apply uniformly — without rewriting the duties themselves.

The unlock

Making SAR an envelope at the boundary — not code inside each duty — is what lets "every duty runs SAR" become true in days instead of weeks. Plain duties behave exactly as before, now with governance around them; richer Sense/Analyze phases become an opt-in, not a rewrite.

02

Three concepts, down from six

technique and kata are retired from the mental model — the capability stack is now Tool → Skill → Duty. The technique/kata code still exists (coupled to task/contract via storage-v2), but the architecture no longer references them. Contributors hold three ideas in their head: Tool, Skill, Duty.

Capability · tier 1

Tool

atomic · typed · in-process

A single typed input → typed output, running in Bun/TS. Hot-path, MCP-exportable, callable by the model via function-calling.

src/tools · ToolRouter + adapters
Capability · tier 2

Skill

declarative · language-agnostic

A markdown-defined capability that can shell out to Python, shell, or anything — not just Bun. Discoverable by manifest. The portable tier.

skills/*/SKILL.md
The decider

Duty

a SAR loop · persona · budget

A unit of work that runs the SAR loop with an allowlist of Skills + Tools. Formerly "Agent." Coordinators like MNGR are simply Duties whose job is other Duties.

duties/ · BaseDuty · DutyRegistry
03

The runtime stack

One event bus, one scheduler. The three things that used to feel like separate orchestrators are now roles within this single spine.

Sensors
Dumb signal sources. Cron, file-watch, webhooks, channel messages. They emit events; they hold no logic.
Event Bus
The only cross-Duty channel. Events carry origin/provenance. No Duty reaches into another's internals.
Duties · SAR
Every Duty is a SAR loop, executed inside the envelope. MNGR is the coordinating Duty; the Plan Workflow is just Todo + Coder duties on the bus.
Capabilities
Tools + Skills. What a Duty is allowed to invoke during Respond, scoped by its allowlist.
Model Router
One path to a model. Providers are adapters behind ToolRouter, selected by tier — local / smart / cloud.
SAR Engine
@ronin/sar. Executor, Chain, MiddlewareStack — the shared machinery the envelope is built from.
04

Providers behind one router

The duplicate provider plugins are gone. Grok, Gemini, and LangChain no longer live as user-facing plugins — they're adapters the router selects, with local Ollama as the privacy-first default.

api.ai.complete() · api.ai.callTools() → ToolRouter → Ollama· Anthropic· OpenAI· Gemini· Cloud

ToolChat sits on top of these two entry points — it is not a third path.

05

What changed

Before
  • 6×capability concepts: agent, plugin, skill, technique, kata, contract
  • 5/57duties actually ran SAR — it was optional middleware
  • 2×provider stacks: grok/gemini/langchain plugins and adapters
  • 3×orchestration paradigms running in parallel
  • ~10contradicting design docs at repo root
After
  • 3×concepts: Tool, Skill, Duty — technique & kata retired from model
  • 57/57duties run under the SAR envelope at the runner level
  • 1×provider path: adapters behind ToolRouter, plugins/langchain kept for graph use
  • 1×spine: Sensors → Bus → Duties, MNGR is a Duty
  • 1×canonical ARCHITECTURE.md; old docs in docs/history/
Deferred removals · not in this pass

The technique / kata / contract / task cluster shares a storage substrate (storage-v2.ts, parser-v2.ts), so removing them is a later project. CLI commands for technique still exist but the architecture no longer references them. This refactor landed: Agent→Duty rename, provider consolidation, SAR envelope at runner.

plugins/grok.ts and plugins/gemini.ts removed — providers are now adapters behind ToolRouter. plugins/langchain.ts and plugins/gemini-cli.ts kept (active use).
