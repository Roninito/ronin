# Ronin On-Device Model Distillation Plan

This folder contains the plan, dataset schema, and synthetic-data generator for training a small on-device model to manage Ronin's tool/event processing.

## Base model

- **Recommended checkpoint:** `LiquidAI/LFM2.5-2.6B-Base`
- **Apple Silicon runtime:** `LiquidAI/LFM2.5-2.6B-MLX`
- **Ollama/LM Studio runtime:** `LiquidAI/LFM2.5-2.6B-GGUF`

### Why LFM2.5-2.6B over Phi-3 Mini

| Concern | LFM2.5-2.6B | Phi-3 Mini |
|---|---|---|
| Parameters | 2.69B | 3.8B |
| Agent/tool use focus | Explicit post-training | General reasoning/coding |
| Context length | 128K standard | 4K default, 128K variant |
| On-device speed | ~220 tok/s on M5 Max, ~113 tok/s on Ryzen | Fast, but larger |
| Fine-tuning stack | LEAP SDK + public Unsloth/TRS notebooks | Transformers/ONNX |
| Native tool format | Built-in tool-call syntax | Not tool-optimized |
| Export formats | MLX, GGUF, ONNX, Transformers | Transformers, ONNX, GGUF |

Ronin's core loop is tool/event orchestration, not raw coding or general chat. LFM2.5 is pre-aligned with that exact workload.

## What "Ronin Manager" will learn

The model is not being trained to write code from scratch. It is being trained to act as the **decider** inside Ronin's SAR loop:

1. **Tool selection** — choose the right `local.*`, `mcp_*`, `skills.run`, or coding-executor dispatch.
2. **Tool argument generation** — emit valid JSON arguments matching the tool's `parameters` schema.
3. **Event interpretation** — read `tool.completed`, `tool.policyViolation`, `task.*`, `PlanProposed`, etc., and decide the next action.
4. **Executor routing** — decide when a task should stay in Ronin vs route to `#claude`, `#opencode`, `#gemini`, etc.
5. **Policy/budget awareness** — respect daily/monthly cost limits, rate limits, and confirmation gates.
6. **Memory/RAG grounding** — use `api.memory.search` results and SecondBrain context when choosing tools.

## Dataset design

See [`dataset-schema.json`](./dataset-schema.json) for the exact JSONL structure.

Each sample is a conversation-style object:

```json
{
  "conversation_id": "ronin-tool-001",
  "system": "You are RoninManager...",
  "messages": [
    { "role": "user", "content": "..." },
    { "role": "assistant", "content": "...", "tool_calls": [...] }
  ],
  "metadata": { "source": "synthetic", "domain": "tool-selection" }
}
```

The model is trained on **multi-turn traces**, not single-shot prompts, because real Ronin execution is a loop.

### Data sources

1. **Synthetic traces** (70-80% of data): generated by [`generate-synthetic-data.ts`](./generate-synthetic-data.ts).
2. **Golden traces** (10-20%): capture real Ronin runs driven by Claude/Opencode and extract the tool-call sequences.
3. **SecondBrain knowledge** (10-15%): project specs, entity notes, and guides are turned into retrieval-grounded tool-selection examples.

## Pipeline overview

```
1. Generate synthetic traces  →  outputs/ronin-model-distillation/dataset/synthetic.jsonl
2. Mine golden traces         →  outputs/ronin-model-distillation/dataset/golden.jsonl
3. Mine SecondBrain context   →  outputs/ronin-model-distillation/dataset/secondbrain.jsonl
4. Merge + split              →  train.jsonl / eval.jsonl
5. Fine-tune LFM2.5-2.6B-Base  →  mlx-lora or mlx-full (Apple Silicon)
6. Export                     →  MLX adapters + GGUF for Ollama
7. Integrate into Ronin        →  modelSelector + OllamaProvider
```

## Step-by-step commands

### 1. Install the Hugging Face CLI (one-time)

```bash
curl -LsSf https://hf.co/cli/install.sh | bash -s
hf auth login   # paste token via secure input, never into chat
```

> **Security note:** The token previously shared in this conversation should be revoked and replaced.

### 2. Download the base model

```bash
mkdir -p models/LFM2.5-2.6B-MLX
hf download LiquidAI/LFM2.5-2.6B-MLX \
  --local-dir models/LFM2.5-2.6B-MLX \
  --include "*.safetensors" "*.json" "*.py" "tokenizer*" "README.md"
```

If `LiquidAI/LFM2.5-2.6B-MLX` is a separate repo, use that exact ID. If the MLX weights are nested inside `LiquidAI/LFM2.5-2.6B`, include the MLX files with `--include "mlx/**"`.

### 3. Generate synthetic data

```bash
cd /Users/ronin/Desktop/bun\ apps/ronin
bun install   # ensure deps present
bun run outputs/ronin-model-distillation/generate-synthetic-data.ts \
  --ronin ./ \
  --secondbrain /Users/ronin/Documents/Obsidian/SecondBrain \
  --out outputs/ronin-model-distillation/dataset/synthetic.jsonl \
  --count 5000
```

### 4. Merge and split dataset

```bash
python3 outputs/ronin-model-distillation/scripts/merge-split.py \
  outputs/ronin-model-distillation/dataset/ \
  outputs/ronin-model-distillation/dataset/train.jsonl \
  outputs/ronin-model-distillation/dataset/eval.jsonl \
  --eval-ratio 0.1
```

### 5. Fine-tune on Apple Silicon with MLX

Install dependencies:

```bash
python3 -m venv .venv-mlx
source .venv-mlx/bin/activate
pip install mlx mlx-lm transformers datasets
```

LoRA fine-tune (recommended first pass):

```bash
python3 - <<'PY'
from mlx_lm import load, generate, train

model, tokenizer = load("models/LFM2.5-2.6B-MLX")

train(
    model,
    tokenizer,
    data="outputs/ronin-model-distillation/dataset/train.jsonl",
    val_data="outputs/ronin-model-distillation/dataset/eval.jsonl",
    adapter_path="outputs/ronin-model-distillation/adapters",
    iters=1000,
    batch_size=4,
    learning_rate=1e-4,
    lora_rank=32,
    lora_alpha=64,
    steps_per_eval=100,
    resume_adapter_file=None,
)
PY
```

For full fine-tune, replace LoRA with full-model training using the MLX `mlx_lm.fuse` workflow.

### 6. Export for Ronin consumption

```bash
# Fuse LoRA into base for a single MLX model
python3 -m mlx_lm.fuse \
  --model models/LFM2.5-2.6B-MLX \
  --adapter-path outputs/ronin-model-distillation/adapters \
  --save-path outputs/ronin-model-distillation/ronin-manager-mlx

# Convert fused model to GGUF for Ollama / LM Studio
python3 - <<'PY'
from mlx_lm import load, generate
from mlx_lm.utils import convert

convert(
    "outputs/ronin-model-distillation/ronin-manager-mlx",
    "outputs/ronin-model-distillation/ronin-manager.gguf",
    quantize=True,
    q_bits=4,
    q_group_size=128,
)
PY
```

### 7. Wire into Ronin

Add to `modelSelector` registry (see `docs/MODEL_MANAGEMENT.md`):

```json
{
  "id": "ronin-manager-2.6b",
  "name": "Ronin Manager 2.6B",
  "provider": "ollama",
  "model": "ronin-manager-2.6b",
  "capabilities": ["completion", "chat", "tools"],
  "contextLength": 131072,
  "tags": ["local", "fast", "tool-router"]
}
```

Create an Ollama Modelfile:

```dockerfile
FROM ./outputs/ronin-model-distillation/ronin-manager.gguf

PARAMETER temperature 0.1
PARAMETER top_k 50
PARAMETER repeat_penalty 1.1
PARAMETER num_ctx 131072

TEMPLATE """{{ if .System }}<|im_start|>system
{{ .System }}<|im_end|>
{{ end }}{{ if .Tools }}<|im_start|>tools
{{ .Tools }}<|im_end|>
{{ end }}{{ range .Messages }}<|im_start|>{{ .Role }}
{{ .Content }}<|im_end|>
{{ end }}<|im_start|>assistant
"""
```

Build and register:

```bash
ollama create ronin-manager-2.6b -f outputs/ronin-model-distillation/Modelfile
ollama run ronin-manager-2.6b
```

Then set it as the default for tool-router decisions in your Ronin config:

```json
{
  "ai": {
    "providers": {
      "ollama": {
        "enabled": true,
        "baseUrl": "http://localhost:11434",
        "model": "ronin-manager-2.6b"
      }
    }
  }
}
```
