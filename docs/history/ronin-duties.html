What Is a Duty?

A Duty is the fundamental unit of work in Ronin. Every agent, bot, scheduler, monitor, and service you see in the system is a Duty. They are TypeScript classes that extend BaseDuty, each with their own schedule, memory, tools, and execution logic.

The SAR Loop

Every Duty runs inside a SAR envelope — Sense, Analyze, Respond — applied at the runner level. This means governance, token budgets, model resolution, and execution tracking are applied uniformly to every duty without any special code.

  • SENSE Pull signal: trigger from cron, webhook, file-watch, or event
  • ANALYZE Reason over context with AI, apply budgets, resolve models
  • RESPOND Execute tools, write memory, emit events, call other duties
Key insight

Duties are not just scheduled tasks. A duty can be a full web application (like the chat UI), a Telegram bot, an event listener, a cron job, or a combination of all of these. The SAR loop wraps whatever the duty does.

Duty Anatomy

import { BaseDuty } from "../src/duty/index.js"; import type { DutyAPI } from "../src/types/index.js"; /** * A Duty is a TypeScript class with: * - Static properties that declare triggers (schedule, watch, webhook) * - A constructor that receives the DutyAPI * - An execute() method containing the main logic * - Optional lifecycle hooks (onFileChange, onWebhook) * - Access to the full DutyAPI: ai, memory, db, http, events, plugins */ export default class MyDuty extends BaseDuty { // Trigger declarations (static properties) static schedule = "*/5 * * * *"; // Cron: every 5 min static watch: string[] = ["./data/*.csv"]; // File watch static webhook = "/api/my-duty"; // HTTP endpoint constructor(api: DutyAPI) { super(api); // Register HTTP routes, event listeners, tools } async execute(): Promise<void> { // Main logic — runs on schedule, event, or webhook const result = await this.api.ai.complete("Hello"); await this.api.memory.store("lastRun", Date.now()); this.api.events.emit("my-duty:complete", {}, "my-duty"); } // Optional: handle file changes async onFileChange(path: string, event: string) { } // Optional: handle webhook requests async onWebhook(payload: unknown) { } }
03

Trigger Types

Duties can be activated by four trigger types, each declared as a static property. A single duty can use any combination.

Trigger 01

Cron Schedule

Standard cron expression. The duty's execute() runs on schedule.

static schedule = "*/5 * * * *"
Trigger 02

File Watch

Watch file patterns. onFileChange() fires on create/update/delete.

static watch = ["./data/*.csv"]
Trigger 03

Webhook

Register an HTTP endpoint. onWebhook() receives the request payload.

static webhook = "/api/my-duty"
Trigger 04

Event Listener

Listen to the event bus in the constructor. React to any duty's events.

this.api.events.on("event", fn)

Creating Custom Duties

Ronin is designed for extensibility. You can create custom duties two ways: manually by writing TypeScript, or using the AI-assisted ronin create-duty command.

Two Ways to Create
  • MANUALWrite TypeScript in ~/.ronin/duties/ — full control, no AI needed
  • AI-ASSISTEDRun ronin create-duty — AI generates the code interactively
Where Duties Live
  • LOCAL./duties/ — project-level, checked into git
  • USER~/.ronin/duties/ — user-level, available across projects
12

Manual Duty Creation

Create a duty by writing a TypeScript file. Place it in ~/.ronin/duties/ for user-level or ./duties/ for project-level. Ronin auto-discovers and hot-reloads.

File Structure

~/.ronin/ ├── duties/ # User-level custom duties │ ├── weather-alert.ts # Your custom duty │ ├── stock-watcher.ts # Another custom duty │ └── ... ├── skills/ # Custom skills ├── plugins/ # Custom plugins └── config.json # Ronin configuration # OR project-level: your-project/ ├── duties/ # Project duties (git-tracked) │ ├── my-duty.ts │ └── ... └── ...
Hot Reload

Both directories are watched. When you save a duty file, Ronin automatically detects the change, reloads the duty, and updates the schedule — no restart needed.

Complete Example: GitHub Release Monitor

// ~/.ronin/duties/github-release-monitor.ts import { BaseDuty } from "../src/duty/index.js"; import type { DutyAPI } from "../src/types/index.js"; /** * Monitors GitHub repositories for new releases. * Runs every 30 minutes, stores seen releases in memory, * and emits events when new releases are found. */ export default class GitHubReleaseMonitor extends BaseDuty { static schedule = "*/30 * * * *"; // Every 30 minutes static webhook = "/api/github-releases"; // Also accessible via HTTP private repos: string[] = [ "ollama/ollama", "oven-sh/bun", ]; constructor(api: DutyAPI) { super(api); this.registerRoutes(); } async execute(): Promise<void> { for (const repo of this.repos) { await this.checkRepo(repo); } } private async checkRepo(repo: string): Promise<void> { const key = `gh-release:${repo}`; // Fetch latest release from GitHub const response = await this.api.http.get( `https://api.github.com/repos/${repo}/releases/latest` ); const release = await response.json() as { tag_name: string; html_url: string }; // Check if we've seen this release before const lastSeen = await this.api.memory.retrieve(key); if (lastSeen !== release.tag_name) { // New release found — store it and emit event await this.api.memory.store(key, release.tag_name); this.api.events.emit("github:new-release", { repo, tag: release.tag_name, url: release.html_url, }, "github-release-monitor"); console.log(`[github-monitor] New release: ${repo} ${release.tag_name}`); } } // Webhook handler — receives push notifications async onWebhook(payload: unknown): Promise<void> { const data = payload as { repository?: { full_name: string } }; if (data.repository) { await this.checkRepo(data.repository.full_name); } } // Register HTTP routes private registerRoutes(): void { this.api.http.registerRoute( "/api/github-releases/repos", async () => Response.json({ repos: this.repos }) ); } }
Important notes

Import paths: Use "../src/duty/index.js" and "../src/types/index.js" — the .js extension is required by Bun's ESM resolver.

Default export: The class must be the export default — Ronin's loader looks for it.

Constructor: Always call super(api) first. Register routes and event listeners in the constructor.

Hot reload: Save the file and Ronin picks it up within seconds. No restart.

AI-Assisted Duty Creation

Use ronin create-duty to have AI generate a complete duty file interactively. The AI asks clarifying questions, then writes production-ready TypeScript.

Step 01

Describe Your Duty

Run the command and describe what you want. The AI asks follow-up questions.

$ ronin create-duty
Step 02

AI Conversation

The AI understands Ronin's architecture and asks about schedule, triggers, APIs needed, and behavior.

What would you like your duty to do?
Step 03

Code Generation

AI generates complete TypeScript with imports, class, static properties, constructor, and execute method.

✅ Duty created: ~/.ronin/duties/my-duty.ts
Step 04

Auto-Reload

Ronin's hot-reload detects the new file, loads the duty, and starts running it immediately.

[hot-reload] Loaded duty: my-duty

CLI Options

# Basic usage — AI will ask questions interactively $ ronin create-duty # Provide description upfront $ ronin create-duty --description "Monitor GitHub repos for new releases" # Save to user-level directory (~/.ronin/duties/) $ ronin create-duty --local # Save to project-level directory (./duties/) $ ronin create-duty --duty-dir ./duties # Specify AI model $ ronin create-duty --ollama-model "qwen3:1.7b" # Skip preview, write immediately $ ronin create-duty --no-preview # Open in editor after creation $ ronin create-duty --edit # When Ronin is running, it uses event-driven creation via orchestrator # When not running, it falls back to direct AI generation
Two creation modes

Event-driven (preferred): When Ronin is running, ronin create-duty sends a create_duty event to the agent-creator-orchestrator, which uses the full SAR pipeline to generate, validate, and hot-reload the duty.

Direct creation (fallback): When Ronin isn't running, the CLI creates the API directly, runs an interactive AI conversation, generates the code, validates it, and writes the file. You then start Ronin to load the new duty.

The DutyAPI Reference

Every duty receives a DutyAPI object in its constructor. This is the single interface to all of Ronin's capabilities — AI, memory, database, HTTP, events, plugins, and more.
